REROLL

Discover hidden roguelike and roguelite gems on Steam.

Working prototype · iOS 17+ · Not yet released

REROLL is a swipe-based discovery app for roguelike and roguelite games. Instead of browsing best-seller lists dominated by titles everyone already owns, players flip through a daily deck of cards and surface games that are gaining momentum but have not broken through yet.

This page exists to accompany a commercial licensing inquiry to IGDB. It describes what the app is, what data it uses today, and exactly what we would like to license.

The discovery model

The core of the product is a ranking signal we built and validated ourselves, not a generic popularity chart:

  • Discovery scoreReviews received in the last 7 days ÷ total lifetime reviews. A game with sudden recent momentum ranks above a game with a large but static review count.
  • Eligibility window100–5,000 total reviews. The lower bound filters out titles with too little signal; the upper bound excludes games that are already well known.
  • No rating filterPositive-review percentage is displayed but never used to filter. Divisive games are part of the point.
  • Catalog sizeApproximately 2,290 roguelike / roguelite titles are currently tracked. The figure moves with each nightly rebuild.
  • RefreshRebuilt nightly by an automated batch job (GitHub Actions).

These parameters are still being tuned. The thresholds, and the way cards are selected for each deck, are likely to change both before and after release. The figures above describe the current build rather than a fixed specification.

Data sources today

The prototype is currently built on Steam data: store search pages for the catalog, the appreviews endpoint for review statistics, and appdetails for descriptions, screenshots and trailers. Cover artwork is Steam's library capsule imagery.

We are contacting IGDB before release because we would rather have the artwork and metadata layer licensed under agreed commercial terms from day one than sort it out afterwards.

Expected request volume

  • Client-side callsNone. The iOS app never contacts IGDB directly.
  • Server-side callsA single nightly batch job resolves metadata for the tracked catalog. With batched queries this is on the order of tens of requests per night, not thousands.
  • DeliveryThe batch output is a single static JSON file served over HTTPS. The app downloads and caches it. Request volume therefore does not scale with user count.
  • AttributionWe will display IGDB attribution wherever your terms require it.
